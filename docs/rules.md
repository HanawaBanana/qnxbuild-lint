# Rules

Generated by `tools/gen_rules_doc.py` from the tables in `qnxbuild_lint/`.
Do not edit by hand; run the script instead (CI fails when it is stale).

Every rule is grounded in the QNX SDP 8.0 `mkifs` reference
(attribute list, inline-file and script-scope sections) or in the QNX
recursive Makefile model (`LIST=` plus `include recurse.mk`).

## Diagnostics

| Rule | Severity | Meaning |
|---|---|---|
| `ATTR_BAD_TYPE` | error | type= value is not one of link/fifo/file/dir |
| `ATTR_BARE` | error | attribute token has neither a +/- prefix nor =value |
| `ATTR_CONFLICT` | error | contradicting attributes in one group, e.g. [+raw -raw] |
| `ATTR_DUPLICATE` | warning | the same attribute appears twice in one group |
| `ATTR_EMPTY_VALUE` | error | value attribute given an empty value |
| `ATTR_KIND` | error | boolean and value attributes were written in the wrong form (+x vs x=y) |
| `ATTR_NOT_LEADING` | error | attribute group does not start the line |
| `ATTR_SPLIT_GROUPS` | error | two attribute groups on one line; mkifs accepts only one |
| `ATTR_UNKNOWN` | error | attribute name is not in the mkifs attribute list |
| `FILE_DUPLICATE_TARGET` | warning | two entries write the same path; mkifs silently keeps the last |
| `IO_MISSING` | error | path given on the command line does not exist |
| `LINK_NEEDS_TARGET` | error | [type=link] needs a name=target file specification |
| `MAKE_CYCLE` | error | include/recursion cycle would make the build loop |
| `MAKE_DUP_RECIPE` | warning | target defined with more than one recipe |
| `MAKE_MISSING_INCLUDE` | error | included makefile does not exist (and is not -include) |
| `MAKE_MISSING_VARIANT_DIR` | error | LIST= variable names a directory that does not exist |
| `MAKE_ORPHAN_RECIPE` | error | recipe line with no preceding rule |
| `MAKE_SPACE_RECIPE` | error | recipe line indented with spaces; make aborts 'missing separator' |
| `MAKE_UNREADABLE` | error | makefile could not be read |
| `SECTION_UNKNOWN` | error | bare [name] header that is not an mkifs attribute (e.g. [block]) |

## Attributes accepted by the parser

Boolean attributes (written `+name` / `-name`, `?` makes them conditional):

`autolink`, `big_pages`, `bigendian`, `compress`, `dupignore`, `followlink`, `include`, `keeplinked`, `optional`, `page_align`, `raw`, `script`, `session`

Value attributes (written `name=value`):

`action`, `autoso`, `cd`, `chain`, `cksum`, `dperms`, `drop`, `filter`, `gid`, `ifs_csa`, `image`, `keepsection`, `linker`, `module`, `mount`, `mtime`, `pagesizes`, `perms`, `phys_align`, `physical`, `prefix`, `ram`, `search`, `sha256`, `sha512`, `type`, `uid`, `virtual`

`type=` values: `dir`, `fifo`, `file`, `link`.

Anything else in an attribute group is reported as `ATTR_UNKNOWN`; a
bare `[name]` header whose name is unknown is reported as
`SECTION_UNKNOWN` (typical of buildfiles borrowed from another build
system, e.g. a Meson-style `[block]` section).
